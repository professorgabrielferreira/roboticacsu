Manual de Programação do Robô Educacional

Guia de estudo para a Equipe Olímpica, com autoavaliação de progresso

Cada etapa abaixo é uma capacidade que o robô precisa demonstrar com confiança, principalmente durante uma prova de robótica, quando não há segunda chance.

Etapa 1 — Inicializar corretamente todos os seus componentes

O robô deve, ao ser ligado, reconhecer com precisão quais pinos correspondem a entradas (botões) e quais correspondem a saídas (motores), além de garantir que inicia sempre em estado de repouso total, sem movimentos residuais que comprometam a segurança ou a previsibilidade da prova.

Etapa 2 — Monitorar continuamente o ambiente de entrada

O robô deve ser capaz de permanecer em observação ininterrupta, sem perder nenhum evento de acionamento dos botões, mesmo operando em alta frequência de verificação.

Etapa 3 — Distinguir um toque real de uma interferência elétrica

O robô deve filtrar ruídos elétricos naturais do contato físico dos botões (bouncing), reconhecendo como válido apenas um acionamento estável e intencional. Essa capacidade é crítica em competições, onde falhas de leitura podem gerar comandos indesejados.

Etapa 4 — Armazenar uma sequência de comandos com integridade

O robô deve registrar, em ordem exata, cada comando escolhido pelo estudante, respeitando um limite máximo de memória sem sobrescrever ou corromper dados já gravados.

Etapa 5 — Reproduzir fielmente a sequência programada

O robô deve executar, comando a comando, exatamente a sequência gravada, sem alterações de ordem, omissões ou repetições indevidas, garantindo pausas de estabilização entre movimentos.

Etapa 6 — Permitir reinício controlado do sistema

O robô deve descartar completamente uma sequência gravada quando solicitado, retornando a um estado limpo, pronto para uma nova programação, sem exigir novo carregamento de firmware.

Nomenclatura técnica da estrutura de um programa em C++ para Arduino, essencial para dialogar com documentação e provas teóricas de nível olímpico.

Diretivas de pré-processador (#define)

Antes da compilação, o pré-processador substitui os nomes simbólicos definidos por seus valores numéricos correspondentes. Melhora a legibilidade e evita "números mágicos" espalhados pelo programa.

Variáveis globais e constantes

Declaradas fora de qualquer função, ficam acessíveis a todo o programa. Inclui um vetor (array) de tamanho fixo, definido por uma constante, usado como estrutura de dados para o armazenamento sequencial dos comandos, e uma variável de índice que controla a posição atual de escrita nesse vetor.

Função setup()

Função especial, executada uma única vez após a energização do microcontrolador. É o ponto de entrada de inicialização do programa, análogo a uma rotina de boot em sistemas embarcados.

Função loop()

Função especial de execução cíclica indefinida, chamada repetidamente pelo firmware do Arduino após o setup(). Representa o laço principal (main loop) característico de sistemas reativos em tempo real.

Funções definidas pelo usuário

O programa é decomposto em funções especializadas, cada uma com uma única responsabilidade (leitura de botão, gravação de comando, execução de sequência, controle de cada motor). Esse princípio é a decomposição funcional, ligada ao conceito de coesão em Engenharia de Software.

Estrutura condicional (if)

Utilizada para tomar decisões binárias, como verificar se um botão específico foi pressionado antes de executar a ação correspondente.

Estrutura de seleção múltipla (switch case)

Direciona o fluxo do programa conforme o valor armazenado em cada posição do vetor de comandos, sendo mais eficiente e legível do que uma cadeia extensa de if / else if nesse contexto.

Estrutura de repetição (for)

Percorre sistematicamente todo o vetor de comandos gravados, elemento a elemento, até o índice final da sequência.

Estrutura de repetição condicional (while)

Aplicada na rotina de detecção de botão para aguardar, de forma bloqueante, a liberação física do botão antes de prosseguir, evitando múltiplos registros de um único toque.

Retorno de valores booleanos (bool)

A função responsável por validar o acionamento de um botão retorna um valor lógico (verdadeiro ou falso), permitindo reutilizar essa verificação em múltiplos pontos do programa sem duplicação de lógica.

Essa arquitetura corresponde a uma máquina de estados simplificada (finite state machine), conceito frequentemente cobrado em provas teóricas e essencial para sistemas embarcados mais complexos.

Bloco 1 — Entendendo como o robô funciona por dentro

Meta 1.1 — Consigo explicar, sem olhar o código, o que cada parte do programa faz (as configurações do começo, o que roda uma vez, o que roda sem parar, e as receitinhas que o programa usa para cada tarefa).

Meta 1.2 — Consigo explicar por que o robô não confia em um clique só e espera confirmar se o botão foi realmente apertado.

Meta 1.3 — Consigo explicar a diferença entre "se acontecer isso, faça aquilo", "repita várias vezes" e "escolha entre várias opções", e dizer onde cada um é usado no robô.

Bloco 2 — Pensando como um programador

Meta 2.1 — Consigo desenhar ou explicar, passo a passo, como o robô guarda na memória cada movimento que o estudante escolhe.

Meta 2.2 — Consigo desenhar ou explicar, passo a passo, como o robô pega tudo que foi guardado e executa na ordem certa.

Meta 2.3 — Se o robô fizer algo estranho (por exemplo, repetir o último movimento duas vezes), consigo imaginar em qual parte do programa pode estar o problema.

Bloco 3 — Colocando a mão na massa

Meta 3.1 — Consigo explicar como os sinais enviados aos motores fazem o robô ir para frente, para trás, ou virar para os lados.

Meta 3.2 — Montei o circuito de exemplo (com o LED) e testei se ele funciona do jeito esperado.

Meta 3.3 — Consegui alterar o exemplo do LED para fazer algo diferente (por exemplo, dois tipos de piscada) sem quebrar o que já funcionava.

Bloco 4 — Preparando ideias para a competição

Meta 4.1 — Tenho uma ideia de algo para melhorar no robô (um novo movimento, um som, mais espaço de memória) e sei explicar por que essa mudança ajudaria.

Meta 4.2 — Consigo explicar como autonomia, precisão nos movimentos, repetir sem erro e lidar bem com falhas (assuntos deste material) aparecem nos critérios de provas como a OBR.

Este exemplo não é o robô da Equipe Olímpica, mas um sistema simplificado que reproduz a mesma lógica de programação em uma escala menor. A ideia é compreender, na prática, os conceitos das abas anteriores antes de enfrentar a complexidade total do sistema com motores.

Aqui, em vez de mover um robô, o programa acende um LED. Em vez de quatro botões de direção, existe apenas um botão de gravação e um botão de execução. A estrutura lógica, porém, é a mesma: ler um evento, armazená-lo em memória, e reproduzi-lo posteriormente.

Gravador de Piscadas do LED

#define BTN_GRAVAR   2
#define BTN_TOCAR    3
#define LED          4

const byte MAX_EVENTOS = 10;
byte sequencia[MAX_EVENTOS];
byte indice = 0;

void setup()
{
    pinMode(BTN_GRAVAR, INPUT_PULLUP);
    pinMode(BTN_TOCAR, INPUT_PULLUP);
    pinMode(LED, OUTPUT);
    digitalWrite(LED, LOW);
    Serial.begin(9600);
}

void loop()
{
    if (botaoPressionado(BTN_GRAVAR))
        gravarEvento();

    if (botaoPressionado(BTN_TOCAR))
        reproduzirSequencia();
}

bool botaoPressionado(byte pino)
{
    if (digitalRead(pino) == LOW)
    {
        delay(25);
        if (digitalRead(pino) == LOW)
        {
            while (digitalRead(pino) == LOW);
            delay(25);
            return true;
        }
    }
    return false;
}

void gravarEvento()
{
    if (indice >= MAX_EVENTOS)
        return;

    sequencia[indice] = 1;
    indice++;
    Serial.println("Evento gravado.");
}

void reproduzirSequencia()
{
    Serial.println("Reproduzindo...");

    for (byte i = 0; i < indice; i++)
    {
        digitalWrite(LED, HIGH);
        delay(300);
        digitalWrite(LED, LOW);
        delay(300);
    }

    Serial.println("Fim da sequência.");
}
